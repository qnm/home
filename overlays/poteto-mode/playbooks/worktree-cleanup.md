## Steps

- **Before** "1. Snapshot and audit. Record `df -h /`": 0. Attribute the volume first. Compare used space on the data volume with what the candidates really hold, and size the other large stores: container, VM and sandbox stores (Docker sandboxes, microsandbox, colima) and the nix store. Prune the largest real holder first. The user naming worktrees as the culprit is a premise to test, not the plan.
- **In** "1. Snapshot and audit. Record `df -h /`": on macOS `/` is the sealed system volume, so record `df -g /System/Volumes/Data`, plus `/nix` when it is its own volume. The audit's SIZE column and `du` give apparent size. Where a package manager clones files from a store (pnpm on APFS), trees share blocks, so SIZE overstates what a prune frees. Rank and report savings by the used-space change on the volume.
- **In** "then run `skills/poteto-mode/scripts/worktree-audit.mjs`": run the wrapper instead, `node ~/Developer/qnm/home/worktree-audit/audit.mjs [--prs prs.json] [repo-path]`. It runs the upstream audit with three changes. Ignored names listed in `disposable.txt` beside it count as rebuildable, so add a repo's cache names there. `--prs` reads the PR list from a file, for when `gh` fails inside the script, and the warning prints the command that writes the file. A LAST_CHAT date shared by every row is printed as `?`. Run it before anything in the session prints worktree paths, because the transcript scan counts the running session as a chat that touched every path it printed.
- **In** "2. The bucket is advice, not permission.": a column with one value on every row, or a warning that a dependency failed (an empty PR column after `gh` failed), is a failed gate. Get that fact another way: rerun with `--prs` for an empty PR column, and get the in-use set from the user for a `?` in LAST_CHAT, before any removal.
- **In** "4. Pause on irreversible loss.": approval given after you promised a check covers the check only. Show the check's results, then get a second yes for the irreversible step.
- **In** "5. Prune the confirmed set.": worktrees that hold `node_modules` take minutes each to remove, so run the loop in the background from the start. Inside the loop, re-check `git status --porcelain` on each path right before you remove it. Hand an `rm -rf` outside the repo to the user as its own `!` command, since a hook can refuse it from the agent.
- **After** "5. Prune the confirmed set.": deleting branches too removes the safety that branch refs give, so it needs its own gate. In a squash-merge repo, ancestry to trunk says nothing. A branch counts as merged only when its local tip is the merged PR's head or an ancestor of it. "The PR merged" alone misses local commits that never reached the PR, so hold those. Before any `git branch -D`, write each name and tip SHA to a restore file outside the scratchpad. Tell the user the file only works until `git gc` prunes the commits, unless a remote copy holds them (the merged PR's head ref, or trunk).
- **In** "6. Simulators and other reclaimers.": every reclaimer passes the gates of steps 2 to 4.
  - Read last use from the tool's own dry run (`sbx prune --dry-run`). A listing's date column is usually creation time.
  - Before you hand over a reclaim command, predict what it frees with a read-only query run as the identity that will run it (dead store paths, profile generations per owner), and measure again after it runs.
  - A `!` command has no terminal. Read the subcommand's `--help` for its non-interactive flag and include it, and send `sudo` to a real terminal.
- **In** "before and after with space reclaimed, the worktrees pruned": report the used-space change on the data volume, measured before and after.
