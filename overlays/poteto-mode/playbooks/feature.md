## Throughput checkpoint

- **In** "Write the throughput checkpoint as four todo items.": make it five. Add:
  - **Independent deliverables.** List every fix the ticket asks for, including any "Also in this card" add-on. A fix with its own files and its own failure mode gets its own branch off trunk and its own PR. Name the PR plan before writing code. The ticket's scope is not the PR's scope.
- **After** "If one worker is best, name why.":
  - **The worktree you're in isn't exclusive while you run anything there**, and an install counts. A worktree isolates files only. State outside the tree, such as a local Docker stack, its generated keys and its queues, is shared by every worktree. Run that state's setup and its suites from one worktree at a time, and re-run setup in the worktree right before each suite.
  - **An `isolation: "worktree"` delegate hands back an uncommitted diff.** A guard can block every `git commit` in `.claude/worktrees/agent-*`, `--dry-run` included. Brief it to stage its work in logical units and report the paths. Review the diff, carry it over with `git -C <wt> diff --no-ext-diff --binary HEAD > <patch>` and `git apply`, rerun the suites, and commit with hooks in your own worktree.
  - **Prove the environment before the spawn.** The install has finished with a captured exit code of 0, and the delegate's test command runs. A delegate spawned before that returns code nobody has run, and a credential failure reaches the human late.
  - **Mutation check, in order, one call per step.** Commit the baseline. Apply the mutation in its own call. Confirm it with `git diff --no-ext-diff`. Run the test in a separate call. Restore with Edit, not `git checkout`. Never put the test in the same parallel batch as the mutation: a denied or failed edit turns the run into a false pass. Report a result only if the diff showed the mutation. Under auto mode the classifier can refuse your mutation edit as weakening a test, so brief the code delegate to run and report the mutation check in its own worktree before it hands back.
  - **Re-read the spec before you write outward.** Before any prod write, and before any status comment on a PR or ticket, fetch the ticket and the PR state again and diff them against the brief. People and other sessions edit both mid-task.
